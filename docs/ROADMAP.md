## 一、P0：近期就该做（影响体验或埋雷）

### 1.1 拆分前端单文件（技术债，越拖越贵）
`app.js` 已近 4800 行，把所有模块（剪贴板 / 聊天 / 网站 / 管理后台 / 阅读模式 / 编辑器）揉在一起。

- 按域拆成 `public/modules/{clip,chat,sites,admin,editor,read}.js`，用 ES Module 引入；
- 构建脚本 `scripts/build-pages.mjs` 目前只打包 `src/worker.js`，需要同时支持多入口打包前端（esbuild 已具备能力）；
- **风险**：拆完必须全量冒烟（登录 / 发板 / 聊天 / 建站四主流程），建议先拆最独立的 `sites` 模块试水。

### 1.2 消掉聊天列表的 N+1 查询 ✅ 已完成（v4.20.0）
`GET /api/chat/conversations` 对每个会话串行发起 3–5 次查询（最后一条消息、对方信息、成员数、留存上限），
会话一多就是几十次 D1 往返。

- 改成：先一次查出所有会话 → 用 `WHERE conv_id IN (...)` 批量取最后消息与成员数 → 内存里拼装；
- 留存上限 `chatRetentionLimit` 也可批量算（一次查所有相关群主 / 对方的 VIP 状态）。

### 1.3 网站托管的「改完看不到」问题（KV 最终一致）⏭ 用户决定暂缓（2026-09-27）
实测 KV 传播约 30 秒，用户明确表示「几十秒延迟问题不大，忽略即可」。以下方案留档，待哪天觉得碍事再做：


- 编辑器保存成功后，把访问链接带上一次性版本号（如 `?v=<时间戳>`）并提示「用这个链接立刻看最新」；
- 或者把用户站的缓存时间降到 60s，牺牲一点命中率换即时性；
- 长期看：文件发布时同时写一个 `sites/{slug}/__version`，托管 worker 命中版本变化就绕过缓存。

### 1.4 `sites.hits` 是建了不用的死列 ✅ 已完成（v4.20.0，已删列）
`sites` 表有 `hits` 字段，但代码里只有 `SELECT`、从来没有 `UPDATE`，访问统计等于没做。

- 要么在托管 worker 里异步累加（注意：Pages Functions 里写 KV/D1 要小心配额与并发）；
- 要么直接删掉这一列，避免误导后来人。

### 1.5 聊天轮询改成按需 ✅ 已完成（v4.20.0）
已改为递归 `setTimeout`：后台（页面不可见）30s、前台 4s，回前台立刻补一次；并新增全局未读轮询（后台 30s / 前台 15s）+ 导航栏闪烁红点。
原问题：固定间隔 `setInterval`，页面开着就一直打接口。

- 页面隐藏（`document.hidden`）时把间隔拉长到 30s 或直接暂停，回到前台立刻补一次；
- 长期可评估 SSE / Durable Objects 长连接，但要权衡 Workers 免费额度和复杂度。

### 1.6 站点治理（封禁 / 举报）✅ 已完成（v4.20.0）
规划里写了「管理员可封禁、用户可举报」，但此前只有后端接口、没有任何入口，等于没落实。现已补齐：
- 管理后台「🌐 站点」tab：搜索 / 筛选 / 封禁（填原因）/ 解封 / 删除；
- 「🌐 我的网站」页「⚠ 举报站点」→ 统一工单（`related_site_slug`），工单详情可一键封禁或删除站点；
- 封禁后：托管侧 403、编辑器禁用改动入口、后端二次拦截、站内通知站长。
- ✅ v4.21.0 续：权限细化（`view_sites` / `ban_sites` / `delete_sites` 三档递进）、封禁页与站内「📮 一键申诉」、工单新增 `appeal` 申诉分类、下架站点不再可访问、用户站右下角可关闭的悬浮举报按钮。

### 1.7 设计一个正经的 logo ✅ 已完成（v4.23.0 定稿）
原来站点图标（favicon）只是 emoji 📋 占位，侧边栏品牌位也是 emoji。v4.22.0 已正式落地。
- **设计语言**：紫底圆角方块（`#5439A3`，注意：实际交付主色是 `#5439A3`，比初稿设想的 `#4f46e5` 更偏紫、更贴 mdqp）+ 白色文档与 `#` 字符，呼应「Markdown 文档 / 快速粘贴」；完整标志母版再叠加浏览器窗口三点 + 斜箭头（呼应 qsites 一键建站）。
- **小尺寸策略**：完整标志在 28px 已糊，故 favicon / 导航品牌位 / PWA 图标统一采用「方块 + 白文档 #」应用图标形态（16px 仍清晰）；完整标志母版留给关于页 / 文档大图。
- **交付资产（均在 `public/`）**：`favicon.svg` + `favicon-{16,32,48,180,192,512}.png`、`mdqp-icon.svg`（完整矢量母版，窗口视口与三点用 `fill-rule="evenodd"` 真挖空）、`mdqp-logo-horizontal.svg`、`mdqp-wordmark.svg`、`manifest.webmanifest`。
- **代码接入**：`index.html` 的 `<link rel="icon">` 改 `/favicon.svg`（+ 16/32 PNG 回退 + apple-touch-icon + manifest）；侧边栏 `.brand-logo` 改 `<img src="/favicon.svg">`；`setFaviconBadge()` 红点角标改以新图标为底。
- **关联**：`public/index.html`、`public/app.js` 的 `setFaviconBadge()`、`public/style.css` 的 `.brand-logo`。

## 二、P1：功能拓展（明显提升产品力）

### 2.1 网站编辑器升级（当前最粗糙的一环） ✅ 已完成（v4.24.1 补齐拖拽+模板）
原来只能「整文件夹上传 / 粘贴 HTML / 单文件编辑」，没有预览、没有结构。

- ✅ 左侧文件树 + 右侧编辑器（行号 textarea，随滚动同步）；
- ✅ 内嵌预览 iframe（`sandbox` 属性限制脚本，本地资源内联成 srcdoc），边改边看；
- ✅ 拖拽上传并显示进度条（整片工作区可拖入文件 / 文件夹，单文件 PUT 带真实进度，v4.24.1 落地）；
- ✅ 内置 4 套入门模板（个人主页 / 作品集 / 小游戏 / 简历），一键套用（v4.24.1 落地）；
- ✅ 支持「新建文件 / 重命名 / 删除」，而非只能覆盖已有路径（新增后端 `POST /api/sites/:slug/rename`）。

### 2.2 站点访问统计 ✅ 已完成（v4.24.0）
配合 1.4 落地：

- ✅ 站点卡片显示累计访问量、近 7 天趋势（迷你柱）；
- ✅ 只统计页面主文档（`index.html` 及各目录首页，托管侧 `recordVisit` 仅在 published + HTML 主文档命中时计数），静态资源不计，避免数字虚高；
- ✅ 托管侧用 KV 异步写（`ctx.waitUntil`，不在请求关键路径做重活），数据落在 `sites/{slug}/__stats`。

### 2.3 站点版本与回滚 ✅ 已完成
- ✅ 每次发布留快照（路由 `POST /api/sites/:slug/snapshots`、`POST .../snapshots/:v/restore`、`DELETE .../snapshots/:v`）；
- ✅ 编辑器内可查看快照列表并一键回滚；
- ✅ 快照配额按 VIP 派生（普通 3 / VIP 5），管理员可批量改，超限自动丢最旧的自动快照。

### 2.4 聊天能力补齐 ✅ 已完成
- ✅ 图片 / 文件消息（`POST /api/chat/upload`，≤5MB，KV 存储，图片内联预览）；
- ✅ 消息撤回（2 分钟内，`POST .../messages/:mid/recall`）、引用回复（`reply_to`）；
- ✅ @提及（每处 50 字内）与已读位置（`POST .../read`）；
- ✅ 群公告（`POST .../announcement`）、群头像（`POST .../avatar`）。

### 2.5 自定义域名（用户呼声会高）
- 允许用户 CNAME 到 `qsites.pages.dev`，后端维护 `sites.custom_domain` 映射；
- 托管 worker 按 `Host` 头反查 slug；
- **Cloudflare Pages 自定义域名需要走 Pages 项目的域名配置**（每个域名都要加），
  量大时不现实 —— 要么限制额度（仅 VIP），要么迁移到支持通配域名的方案（需 DNS + 证书自动化）。

### 3.1 VIP 真实付费（#154 待拍板）

- 用户可把自己站点设为「公开模板」，他人一键复制；

### 3.4 数据导出与迁移

- 既提升信任，也降低「平台跑路」的心理门槛。

## 四、工程质量与流程

### 4.1 修掉 `sync-docs.mjs` 的 spawn 问题
脚本里用 `spawnSync` 调 node/wrangler，在 Windows 沙箱下持续 `EBUSY`，
每次同步 help 都得手工生成 SQL 再跑 wrangler 绕过去。

- 改成直接调用 Cloudflare HTTP API（D1 有 REST 接口）或改成异步 `spawn`；
- 同步失败要有明确退出码和提示，别静默半成功。

### 4.2 自动化冒烟 ✅ 已完成（2026-11-20）
`scripts/smoke.mjs`，只读、不写库，跑一次 22 项检查：

```bash
node scripts/smoke.mjs                       # 检查生产站
node scripts/smoke.mjs https://xxx.pages.dev  # 检查部署预览
```

覆盖：`/api/health` 版本 → 三个公开读接口（确认 D1 没挂）→ 游客接口结构（未登录应 200 且 `authenticated=false`）→ 必须鉴权的接口（要 401/403，**404 说明路由被 SPA 回退吞掉**）→ 静态产物与版本号一致 → 深链接刷新不 404 → **本地 `pages-build` 是否落后于 `src`、本地 VERSION 是否与线上一致**。失败退出码 1。

### 4.3 静态扫描补强
现有扫描查不出「函数体内引用了未声明的顶层变量」和「SELECT 漏列导致映射静默兜底」——
这两类都在本项目复发过多次（v4.15.1、v4.15.3、v4.19.1 各一次）。

- 用 esbuild 打包后做一次未解析标识符检查（比正则扫字符串可靠得多，正则会被模板字符串里的反引号打乱）；
- 对 `|| 1` / `|| null` / `|| 0` 这类兜底写法做人工复核清单。

### 4.4 源码同步 ❌ 仍未解决（且已恶化）
GitHub 同步（Contents API）要走 `GH_PAT`，脚本 `scripts/sync-github.mjs` 现成，但**最后一个 push 停在 2026-09-25**，本地已到 v4.33.0（10-27），**相差一个月、十几个版本**。本地是唯一完整副本。
**这是当前风险最高的一项**：磁盘出问题 = 全量丢失。补 PAT 后按 `CHANGELOG.md`、`src/`、`public/`、`scripts/` 顺序整包推一次，之后纳入发布流程。

## 六、明确不做

- **不做 IE 兼容**（2026-09-07 已拍板）：只需顺利弹出兼容提示并给下载链接。
- **不为 qsites 引入后端运行时**：定位就是静态托管，需要动态能力请另开项目。
- **不把 cpoauth 作为登录主路径**：服务不稳，密码登录兜底必须保留。
