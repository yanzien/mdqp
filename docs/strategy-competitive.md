## 〇、先看数据：别急着加功能

远程 D1 实测（2026-09-03）：

| 指标 | 数值 |
|---|---|
| 剪贴板总数 | **12** |
| 注册用户 | **5** |
| 通知记录 | 5 |

**这是本文最重要的一个数字。** 12 个板、5 个用户，意味着我们现在做的任何"体验优化"都是在给一个空房间换壁纸。

所以优先级必须重排：

- ❌ 不要继续堆功能（我们已经有 8 个高级功能开关、4 类通知、L0–L3 信任等级、徽章、邀请码、VIP、反馈系统……对这个体量来说是**过度设计**）
- ✅ 先回答「**谁会把它用起来，为什么**」，再为这群人做**让他们存下内容**的能力

功能再多，只要用户是"发完拿链接就走"，就留不住——因为**迁移成本为零**。护城河不是功能数量，是用户存在你这儿的内容量。

## 一、竞品事实对标

> 事实基于 2026-09-03 公开资料与实测，标注 ⚠️ 的为待你确认项。

| 维度 | **mdqp（我们）** | 洛谷剪贴板 | note.ms | pastebin / gist |
|---|---|---|---|---|
| 使用门槛 | 免登录可用（游客周 5 个） | 必须洛谷账号 | 零门槛，打开就写 | 多需注册 |
| 链接权限模型 | **六维**：公开/私密/登录可见/密码/定时过期/浏览数上限/唯一读者数上限/协作可编辑 | 仅 `public` 布尔 | **无**（知道 URL 即能改） | 公开 / 私有 / 未列出 |
| 单篇字数 | **300 等效字**（VIP 不限） | 无限制（⚠️ 实测确认） | 无限制 | 免费 512KB 级 |
| 内容归属 | 登录账号 + 可改可删 | 洛谷账号 | **无归属，链接即所有权** | 账号 |
| 编辑历史 | ❌ 无 | ❌ 无 | ❌ 无（覆盖即丢失） | Gist 有 |
| 搜索 / 组织 | ⚠️ 仅搜**公开**板，不搜自己的私有板；无标签/收藏/置顶/排序 | 有列表页 | ❌ 无（靠记 URL） | Gist 有搜索 |
| 评论 / 社交 | ✅ 评论 + @提及 + 个人主页 + 通知 | ❌ | ❌ | ⭐ star / fork |
| Markdown 质量 | ✅ KaTeX 数学公式 + 代码高亮 + TOC + 一键语法修复 | ✅ Markdown + LaTeX（洛谷生态） | 基础 Markdown | 弱 |
| 竞赛身份 | ✅ cpoauth 聚合洛谷/CF/AtCoder/GitHub 等 | 仅洛谷本家 | ❌ | ❌ |
| 移动端写作 | ⚠️ ≤860px 单列堆叠，未专门优化 | 一般 | ✅ 极简天然适配 | 一般 |
| 开放 API | ❌ 无 | 有非官方 API | ❌ | ✅ 官方 API |
| 国内直连 | ✅ `mdqp.pages.dev` 直连 | ✅ | ✅（⚠️ 稳定性存疑） | ❌ pastebin 需梯子 |
| 广告 / 干扰 | 无 | 洛谷站内 | 无 | pastebin 有广告 |

**一句话总结**：在**权限控制粒度**上我们碾压所有竞品；在**内容组织与检索**上被所有竞品碾压；在**字数**上自废武功。

## 二、我们真正的优势（哪些是护城河，哪些是自嗨）

### 2.1 真护城河 —— 只有 3 条

**① 权限六维（唯一一家）**
公开 / 私密 / 登录可见 / 密码 / 定时过期 / 浏览数上限 / 唯一读者数上限 / 协作可编辑。
竞品最多做到 public/private 二选一。这是**真正有人会专门为它而来**的能力：发答案、发答案案、发临时密钥、发给限时看的人。

**② 身份 + 内容沉淀（半成品，但地基在）**
账号归属、可改可删、评论 @、通知、个人主页。note.ms 的用户永远不敢存重要东西——因为链接丢了就全没了。我们有账号，就有可能成为"存东西的地方"。
⚠️ **但当前半成品**：没有组织能力，沉淀下来的 12 个板等于沉进海底。

**③ OI 垂直身份层（独家）**
cpoauth 把洛谷 / Codeforces / AtCoder / GitHub 聚到一张名片上。洛谷自己只认洛谷，我们跨平台。这是竞品结构上做不到的。

### 2.2 自嗨 —— 别再吹了，也别再投入

| 项 | 为什么是自嗨 |
|---|---|
| **信任等级 L0–L3** | 没有任何实际权益。用户升到 L2 得到了什么？**什么都没有。** 昨天刚改成"维持制"，不达标会掉级——**只罚不赏，用户只会觉得莫名其妙**。这是当前最危险的改动，见 §3-S1 |
| **成就徽章** | 装饰品。Discourse 的徽章有价值是因为它绑定权限（L3 能发链接、能改分类），我们的徽章不绑定任何东西 |
| **邀请系统** | 没有可发放的权益，邀请动机为零。`invite` 表历史上从未写入过数据，功能持续失效——没人邀请，也没人在乎 |
| **VIP** | 无支付路径、无权益清单、靠 admin 手动发。当前唯一的实际权益是"不限字数"，而字数限制本身是错的（见 §3-S2） |
| **战绩概览** | 上游 cp:summary 未放行 scope，只剩一张 cpoauth 的 `card.svg`。**那是 cpoauth 的能力，不是我们的**，随时可被摘走 |

**判断标准**：一个功能，用户会不会为了它注册 / 回来？不会，就是自嗨。

## 三、致命短板（按流失严重度排序）

### S1 · 信任等级"只罚不赏" 🔴 最紧急
v4.5.2 刚把 L2/L3 改成维持制，需要近 14 天 5 个板 + 邀请 1 人。**但等级没有任何权益**。
后果：用户看到"你还差 3 个板就要掉级"只会困惑——掉级有什么损失？没有。那为什么要努力？
**这是纯粹的心理负向激励**，必须立刻补权益矩阵（P0-4）。

### S2 · 300 字上限，自废武功 🔴
300 等效字**放不下一个带注释的快速排序模板**，更别说题解。
用户第一次认真写东西就被打断，这个体验直接把"工具站"降级成"便签站"，而便签站有更极简的 note.ms。
同时 VIP 卖点"不限字数"成了**用来解锁本就不该被限制的东西**——错误的商业模式。

### S3 · 无草稿 / 自动保存 🔴
`grep beforeunload|autosave` → **零命中**。
写一半刷新、发布失败、手滑关标签 = **内容全丢**。对工具站来说这是信任崩塌级问题。note.ms 是输入即存，我们反而更差。

### S4 · 内容不沉淀：无标签/收藏/置顶/排序 🟠
「我的」有列表，但只能翻。12 个板时无所谓，200 个板时等于没有。
**这直接决定用户会不会把 mdqp 当"库"而不是"一次性通道"。**

### S5 · 首页搜索只搜公开板 🟠
`GET /api/clips` 硬编码 `WHERE is_public = 1`。
用户搜自己的私有板 → 搜不到 → 以为丢了。**私有的东西搜不到，等于没存。**

### S6 · 无开放 API / 导入导出 🟠
`grep export|download` → 零命中。
程序员用户（我们的目标人群）习惯 `curl paste` / 一键导出 .md。没有 API = 进不了工作流 = 永远只是网页玩具。
同时**用户数据不可带走**，长期反而降低信任。

### S7 · 首屏资源偏重 🟡
`index.html` 同步加载：`marked 35KB + purify 21KB + qrcode 20KB + katex.min.js 272KB + katex.css 25KB ≈ 373KB`。
其中 **katex 272KB 只有含 `$` 数学公式的板才用得上**，却每个访客都要下。另有 `highlight.min.js 1.05MB`（全语言包）、`wechat-qr.png 474KB`。
对比 note.ms 几乎零资源 —— "快"就是它的全部卖点，我们不能在这条上输太多。

### S8 · 移动端未打磨 🟡
`style.css` 只有 6 个 `@media`，编辑器在 ≤860px 只是简单单列堆叠（`min-height: 420px` 两栏叠成一长条）。手机上能写，但不好写。
学生用户大量场景在手机上。

### S9 · 冷启动 / 无增长路径 🟡
12 个板、5 个用户。无 SEO（公开板无 og 卡片、无 sitemap）、无广场、无内容可被搜索引擎发现 → 零自然增长。

### S10 · 备份与数据可携带 🟢 远期
D1 有导出，但用户侧无"导出我所有内容"。

## 四、用户为什么要用我们？（定位重述）

### 4.1 现在的一句话答案是站不住的

"粘上就走、拿链接就分享" —— 这句话 note.ms 做得更好（零门槛、输入即存）。**我们不能用别人的强项当卖点。**

### 4.2 应该改成这个定位

> **OI / 算法选手的 Markdown 代码片段库。**
> 写一个模板，存下来三个月后还能搜到；发出去，能证明这是你写的。

三根支柱，各自对应一个竞品做不到的点：

| 支柱 | 用户价值 | 对标谁 |
|---|---|---|
| **A. 存得下、找得到** | 个人模板/题解库，可检索、可组织、有历史 | 打 note.ms（无归属无搜索）、打洛谷剪贴板（无标签） |
| **B. 控得住** | 密码 / 过期 / 读者数 / 浏览数，发东西不再裸奔 | 打所有（唯一一家） |
| **C. 认得出** | 竞赛身份名片 + 模板归属，作品挂在真人账号下 | 打匿名存站 |

### 4.3 目标用户画像（先做窄，别做宽）

**主力**：OI / ACM 选手、算法爱好者，主力需求 = **存模板、存题解、发题解、互相抄模板**。
**次主力**：需要"限时/限量/带密码分享"的任何人（发答案、发配置、发临时凭证）。

**只服务这两群人，其他一概不伺候。** 现在 5 个用户，做宽等于什么都不做。

## 五、提升方案（与 plan-cpoauth.md 未完成项对齐）

### P0 · 止血（建议 1 周内，全部无外部依赖）

| # | 项 | 做什么 | 技术要点 | 验收 |
|---|---|---|---|---|
| **P0-1** | **权益矩阵** 🔴 | 给 L0–L3 / VIP 定义**真实权益**，写进帮助页与「我的」 | 见下方权益表；`/api/me` 返回 `benefits` 与 `next_level_unlock`；「我的」展示"当前权益 / 升到下一级解锁什么" | 用户能说出"升 L2 有什么用" |
| **P0-2** | **字数分级** 🔴 | 默认 300 → **1500**；L2+ **5000**；L3/VIP/admin **不限**（硬上限 20000 防滥用） | `getSiteSetting('global_char_limit')` 改为按 `trustLevel`/`isVip` 分级；`src/worker.js:727` 与 `:869` 两处判定统一 | 能完整发一篇带代码的题解 |
| **P0-3** | **草稿自动保存** 🔴 | 编辑器内容 500ms debounce 写 `localStorage['mdqp_draft_new']`；编辑已有板写 `mdqp_draft_<clipId>`；重进页面自动恢复并提示；离开页面 `beforeunload` 提醒 | 新建页 `renderNew()` 挂载；发布成功后清 key | 写一半杀标签页，重开内容还在 |
| **P0-4** | **我的剪贴板 2.0** 🟠 | 新增 `GET /api/me/clips?q=&tag=&sort=&pinned=`，**能搜自己的私有板** | SQL 见下；前端「我的」加搜索框 + 标签筛选条 + 排序（创建/更新/热度）+ 置顶 | 用户能在 200 个板里 3 秒找到目标 |
| **P0-5** | **资源瘦身** 🟡 | ① katex 改**按需动态加载**（内容含 `$` 或 `$$` 时才 `import('/vendor/katex/katex.min.js')`）；② highlight 换 10 语言子集（C++/Python/Java/JS/JSON/Bash/SQL/Markdown/Go/Rust）或按需；③ `wechat-qr.png` 474KB → 压缩到 <80KB | `public/index.html` 去掉 katex 的 `<script>`/`<link>`，改 `app.js` 里条件加载 | 首屏 JS < 150KB（gzip 前 < 400KB → < 130KB） |

**P0-4 SQL 草案**（加法，可回滚）：

```sql
ALTER TABLE clipboards ADD COLUMN tags TEXT DEFAULT '';      -- 逗号分隔，如 "算法,模板,DP"
ALTER TABLE clipboards ADD COLUMN pinned INTEGER DEFAULT 0;  -- 1=置顶
CREATE INDEX IF NOT EXISTS idx_clipboards_owner_pinned ON clipboards(owner_type, owner_id, pinned DESC, updated_at DESC);
```

## 六、指标：别用"功能上线数"衡量

**北极星指标**：**周活用户中，回来查看或编辑"旧剪贴板"（≥7 天前创建）的比例** —— 内容沉淀率。
理由：这个数字上升 = 用户真的把东西存在这儿 = 迁移成本形成 = 护城河成立。目标：> 30%。

辅助指标：

| 指标 | 当前 | 3 个月目标 |
|---|---|---|
| 注册用户 | 5 | 200 |
| 剪贴板总数 | 12 | 1500 |
| 人均剪贴板 | 2.4 | ≥ 8 |
| 7 日留存 | 未知（无埋点） | ≥ 25% |
| 搜索使用率 | 0（无私有搜索） | ≥ 40% 的登录会话 |
| API 创建占比 | 0 | ≥ 10% |

**⚠️ 前提：先加埋点。** 现在连 DAU 都测不了（`GET /api/stats` 只有 clips/users 总数）。P0 里顺手加一张 `events(id, type, from, uid_or_guest, created_at)` 日聚合表，否则后面所有决策都是拍脑袋。

## 七、现在该做的 3 件事（按 ROI 排序）

1. **字数 300 → 分级 1500/5000 + 权益矩阵**（半天）
   止血。这两个是"用户第一次认真用就会被劝退"和"维持制挨骂"的直接来源，改动只在 `src/worker.js:727`/`:869` 两处 + 帮助页。

2. **草稿自动保存**（约 1 天）
   纯前端 localStorage，零后端改动，直接消除"内容丢失"这个信任杀手。

3. **我的剪贴板 2.0：私有搜索 + 标签 + 置顶 + 排序**（约 3 天）
   这是把 mdqp 从"一次性通道"变成"库"的分水岭。全部内容沉淀能力都依赖它。

## 八、风险与红线

| 风险 | 说明 | 缓解 |
|---|---|---|
| **过度设计复发** | 我们已经有 8 个高级功能开关 + 4 类通知 + 徽章 + 邀请 + VIP，服务 5 个用户 | **每次加功能前问一句**：这让用户更愿意把内容存这儿吗？答不上来就不做 |
| **字数放开 → D1 爆容量** | D1 免费档 5GB 存储。估算：1500 字 ≈ 3KB，1000 DAU × 3 板/天 × 3KB ≈ 9MB/天 ≈ **3.3GB/年**，接近上限 | 分级发放（P0-2 已设硬上限 20000）；游客板 30 天未访问自动清理；过期板定期 purge；真到瓶颈再迁 R2 存正文 |
| **继续加深 cpoauth 依赖** | 它 502 过、scope 不放行、能力是别人的 | cpoauth 只做 **加分项**（身份/名片），**永远不做登录主路径**（密码兜底已有），新功能不得依赖它 |
| **维持制招骂** | 掉级无权益 = 纯负反馈 | P0-1 必须先于/同步于任何等级相关改动上线 |
| **改动破坏线上** | — | DB 只做加法（加列/加表），Pages 每版可回滚，部署前 `sync-docs --check` |
